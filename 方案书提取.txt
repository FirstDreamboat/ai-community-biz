## 一、项目概述
### 1.1 项目背景
“十五五”期间，我国将新开工改造城镇老旧小区**11.5万个**，2026年中央财政安排城市更新专项资金**970亿元**。城市更新领域“十五五”期间投资规模至少达**15万亿元**，存量社区智能化改造项目年增长率保持在**30%以上**。
狄耐克已将老旧小区更新改造、存量项目智能化升级作为市场攻坚重点方向。公司已推出专门面向旧改的“IP两线公寓对讲系统解决方案”，并依托全国**60多个直属办事处、30余个经销网点**实现全国性落地。
然而，老旧小区改造项目信息分散于各级政府网站、招投标平台、住建部门公告等渠道，人工搜集效率低、商机响应慢。本方案旨在构建**AI存量项目商机挖掘系统**，实现从信息采集到商机转化的全链路自动化。
### 1.2 项目目标
- **精准**：自动采集全国老旧小区改造项目信息，AI匹配狄耐克产品方案
- **高效**：商机发现效率提升5-10倍，从“人找信息”变为“信息找人”
- **转化**：生成优先级排序的商机列表和定制化跟进策略，提升中标率
## 二、系统架构
### 2.1 总体架构
系统采用四层架构：
```
┌─────────────────────────────────────────────────────┐
│                   应用展示层                         │
│  商机驾驶舱 │ 项目地图 │ 跟进看板 │ 报表中心        │
├─────────────────────────────────────────────────────┤
│                   智能决策层                         │
│  商机评分引擎 │ 策略生成引擎 │ 竞品分析引擎         │
├─────────────────────────────────────────────────────┤
│                   AI处理层                          │
│  NLP解析引擎 │ 匹配引擎 │ 摘要生成 │ 意图识别       │
├─────────────────────────────────────────────────────┤
│                   数据采集层                         │
│  定向爬虫 │ API接入 │ 定时调度 │ 去重清洗          │
└─────────────────────────────────────────────────────┘
```
### 2.2 技术选型
| 模块 | 技术方案 | 说明 |
|------|---------|------|
| 数据采集 | Python Scrapy + Apify | 支持多源定向爬取 |
| NLP解析 | DeepSeek大模型 | 公司已接入，招标公告语义理解与关键信息抽取 |
| 向量检索 | RAG知识库 | 公司产品/方案向量化存储，语义匹配 |
| 任务调度 | 定时任务框架 | 按日/按周自动采集与更新 |
| 前端展示 | 低代码平台 | 快速搭建商机驾驶舱 |
## 三、核心功能模块
### 3.1 数据采集模块——四源并进
**（1）政府招投标平台**
定向爬取中国政府采购网、各省市公共资源交易中心、住建部门官网等，抓取老旧小区改造相关的招标公告、采购意向、项目审批信息。
**（2）物业与开发商动态**
采集头部物业公司（龙湖、保利、招商蛇口等，均为狄耐克长期合作方）及地方城投公司的项目动态、供应商征集公告。
**（3）政策与规划信息**
自动抓取各级政府的城市更新规划、老旧小区改造年度计划、重点改造片区名单。
**（4）行业资讯与展会**
采集安防行业媒体、智慧社区论坛、行业展会信息，捕捉潜在商机线索。
### 3.2 AI智能解析模块——信息结构化
**（1）公告自动解析**
对采集到的非结构化公告进行文本解析，自动提取**招标方、项目类型、预算金额、时间节点、资质要求、技术参数**等核心字段。
**（2）项目画像生成**
根据解析结果自动生成项目画像，包括：改造规模（户数/楼栋数）、改造内容（对讲系统/门禁/停车/安防等）、资金性质（中央财政/地方配套/自筹）、进度阶段（规划/招标/施工）。
**（3）语义理解与分类**
利用NLP技术判断项目与狄耐克业务的关联度，自动分类为“高相关”“中相关”“低相关”。
### 3.3 智能匹配模块——商机评分
**（1）狄耐克产品知识库**
将公司全系列产品与解决方案（IP两线公寓对讲系统、数字楼宇对讲系统、智慧社区解决方案、智慧停车、紧急求助等）构建为向量化知识库。
**（2）双向匹配运算**
采用三步式AI匹配机制：
- **第一轮**：项目需求标签 ↔ 产品能力标签的粗匹配
- **第二轮**：项目改造条件（如“布线难”）↔ 公司技术方案（如“无需重铺线路”）的深度匹配
- **第三轮**：区域 ↔ 办事处覆盖能力的匹配
**（3）商机评分模型**
综合以下维度对每个项目打分（百分制）：
- **需求匹配度**（40分）：项目需求与公司产品方案的契合程度
- **预算规模**（20分）：项目预算金额大小
- **区域覆盖**（15分）：是否在公司办事处覆盖范围内
- **时间紧迫度**（15分）：投标截止时间、项目启动时间
- **竞争态势**（10分）：已知竞争对手情况
### 3.4 商机推送与跟进模块
**（1）优先级排序输出**
按综合评分从高到低排序，每日/每周自动生成**商机推荐列表**，推送至销售人员。
**（2）定制化跟进策略**
针对不同项目自动生成跟进建议：
- 高评分项目：建议立即联系、准备定制化方案
- 中评分项目：建议进一步调研、准备标准方案
- 低评分项目：建议持续关注、定期复查
**（3）竞品监测**
自动监测竞品（如安居宝、立林等）在老旧小区改造项目中的中标情况，分析其优势区域和产品策略。
### 3.5 数据可视化模块
**（1）商机驾驶舱**：实时展示全国商机总量、区域分布、评分分布、跟进状态
**（2）项目热力图**：在地图上展示各区域老旧小区改造项目密度
**（3）趋势分析**：月度商机变化趋势、区域热度排行、产品需求排行
## 四、实施计划
### 4.1 阶段规划（9.1-11.30，共12周）
| 阶段 | 时间 | 核心任务 | 交付物 |
|------|------|---------|--------|
| **第一阶段：数据基建** | 第1-3周 | 搭建数据采集框架，接入3-5个核心数据源（中国政府采购网、福建/厦门公共资源交易中心等） | 数据采集模块上线 |
| **第二阶段：AI模型训练** | 第4-6周 | 基于历史招标公告训练NLP解析模型，构建产品知识库向量 | 解析准确率达85%以上 |
| **第三阶段：匹配引擎开发** | 第7-9周 | 开发双向匹配算法与商机评分模型 | 匹配引擎上线 |
| **第四阶段：前端与测试** | 第10-12周 | 搭建商机驾驶舱，全链路联调测试，模拟试运行 | 系统完整上线，开始试运行 |
### 4.2 团队配置（建议3-5人跨部门组队）
| 角色 | 人数 | 来源部门 | 职责 |
|------|------|---------|------|
| 项目经理 | 1人 | 研发中心/信息中心 | 整体统筹、进度管理 |
| 数据工程师 | 1-2人 | 信息中心 | 数据采集、清洗、存储 |
| AI算法工程师 | 1人 | 研发中心 | NLP模型、匹配算法开发 |
| 前端/全栈开发 | 1人 | 信息中心/研发中心 | 可视化驾驶舱开发 |
| 业务顾问 | 1人 | 销售/市场部 | 商机评分规则、业务需求确认 |
### 4.3 资源需求
- **开发环境**：公司现有服务器资源或云服务器（用于部署采集、AI服务）
- **数据源**：需申请接入各地公共资源交易平台API或配置爬虫（需遵守robot协议）
- **AI模型**：复用公司已接入的DeepSeek大模型能力
- **预算**：零成本起步，优先使用开源工具和公司现有基础设施

## 六、风险与应对
| 风险 | 应对措施 |
|------|---------|
| 数据源反爬/封IP | 使用代理IP池，控制请求频率，优先使用官方API |
| 公告格式多样解析困难 | 采用多模板适配+AI兜底解析，持续迭代优化 |
| 匹配准确率不足 | 建立人工反馈闭环，定期优化匹配规则和模型 |
| 销售人员接受度低 | 初期以辅助工具定位，逐步培养使用习惯 |
## 七、创新亮点总结
1. **场景精准**：聚焦“十五五”老旧小区改造11.5万个项目的海量商机
2. **技术适配**：结合公司已有AI能力（DeepSeek大模型）和产品优势（IP两线系统）
3. **闭环设计**：从“采集→解析→匹配→推送→跟进”全链路自动化
4. **可量化**：商机评分模型确保每条线索可评估、可追溯
5. **可扩展**：未来可接入更多数据源（物业公司动态、开发商采购计划等），并延伸至智慧医院、智慧酒店等业务线
