## 1. 测试目标与范围

### 1.1 目标
- 验证功能符合《需求规格说明书》全部功能需求。
- 验证非功能需求（性能、安全、可用性）。
- 降低上线风险，保障试运行质量。

### 1.2 测试范围
| 模块 | 范围 |
|------|------|
| 数据采集 | 四类数据源采集、去重、调度、失败重试 |
| AI解析 | 公告解析、画像生成、相关度分类、人工修正 |
| 智能匹配 | 三步式匹配、评分模型、规则配置、重算 |
| 推送跟进 | 推荐列表、多渠道推送、状态流转、逾期提醒 |
| 可视化 | 驾驶舱、热力图、趋势、导出 |
| 系统管理 | 认证、RBAC、数据源管理、审计 |
| 非功能 | 性能、安全、兼容性 |

### 1.3 测试环境
- 测试环境：独立部署（Docker Compose），使用脱敏测试数据。
- 联调环境：模拟数据源（Mock 页面），避免真实抓取依赖。

## 5. 性能测试方案
- 工具：locust。
- 场景：登录、商机列表、驾驶舱、热力图（并发 20/50/100 阶梯）。
- 通过标准：P95 响应 < 3s，错误率 < 1%。
- 产出：压测报告（含基线数据与优化建议）。

## 6. 安全测试方案
- 认证绕过、越权（水平/垂直）、注入、XSS、CSRF、敏感信息泄露。
- 依赖漏洞扫描（pip-audit / trivy）。
- 产出：安全测试报告，P0 漏洞零遗留。

## 7. 缺陷管理流程

```
发现缺陷 → 提交缺陷单（严重程度 P0-P3）→ 开发修复 → 回归验证 → 关闭
```
- 缺陷单要素：标题、复现步骤、预期/实际、环境、截图/日志、优先级。
- 工具：公司统一缺陷管理平台（或 GitLab Issue）。
- 严重程度定义：
  - P0 阻断：无法登录、数据丢失、核心功能不可用
  - P1 严重：主功能缺陷但可绕行
  - P2 一般：功能受限但影响小
  - P3 轻微：界面/文案问题

## 8. 测试准出标准（Exit Criteria）
1. P0/P1 缺陷清零，P2 遗留 ≤ 5 个且已评审确认。
2. 核心功能用例（P0/P1）通过率 100%。
3. 解析准确率抽样 ≥ 85%；高相关判定准确率 ≥ 80%。
4. 性能与安全测试通过（§5、§6 标准）。
5. 自动化回归集全绿。
