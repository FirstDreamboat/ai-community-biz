## 1. 设计目标与约束

### 1.1 设计目标
- **四层解耦**：数据采集层 / AI处理层 / 智能决策层 / 应用展示层独立演进。
- **零成本起步**：优先复用公司现有基础设施（服务器、DeepSeek API、低代码平台）。
- **可扩展**：数据源可插拔，业务线可扩展（智慧医院、智慧酒店）。
- **全链路闭环**：采集→解析→匹配→推送→跟进，数据全程可追溯。

### 1.2 约束条件
- AI 能力复用公司已接入的 DeepSeek 大模型。
- 采集需遵守 robots 协议与数据合规要求。
- 前端优先采用低代码平台快速搭建，必要时定制开发。
- 12 周交付周期（9.1-11.30）。

## 3. 技术选型

### 3.1 选型清单

| 模块 | 技术方案 | 说明 | 理由 |
|------|---------|------|------|
| 数据采集 | Python Scrapy + Apify | 支持多源定向爬取 | 生态成熟、代理/中间件丰富 |
| 后端服务 | Python FastAPI / Django REST | API 服务 | 与爬虫/AI 生态一致，开发快 |
| NLP解析 | DeepSeek 大模型 API | 语义理解、信息抽取 | 公司已接入，零新增成本 |
| 向量检索 | RAG 知识库（Milvus / pgvector / Chroma） | 产品知识语义匹配 | 轻量可自托管 |
| 任务调度 | APScheduler / Celery Beat | 按日/按周自动采集更新 | 轻量、无需额外中间件 |
| 消息队列 | Redis Stream / RabbitMQ | 异步任务解耦 | Redis 复用成本低 |
| 数据库 | MySQL 8.0 | 业务数据主存储 | 公司标准、事务可靠 |
| 缓存 | Redis | 热点数据、去重 Bloom Filter | 高性能 |
| 搜索引擎 | Elasticsearch（可选） | 公告全文检索 | 增强检索能力 |
| 前端展示 | 低代码平台 + Vue3（定制） | 商机驾驶舱 | 快速搭建 |
| 地图可视化 | ECharts + 高德/Leaflet | 热力图、区域分布 | 开源免费 |
| 部署 | Docker + Docker Compose | 一键部署 | 环境一致 |
| 监控 | Prometheus + Grafana（可选） | 服务健康、任务监控 | 开源免费 |

### 3.2 技术决策记录（ADR）

| 编号 | 决策 | 备选方案 | 结论 |
|------|------|---------|------|
| ADR-001 | 爬虫用 Scrapy 而非纯 Requests | 纯 Requests 手写 | Scrapy 自带调度、中间件、去重，节省 2 周 |
| ADR-002 | 解析用 DeepSeek API 而非自训练模型 | 自训练 BERT/NER | 12 周内无法完成高质量标注训练，API 即插即用 |
| ADR-003 | 向量库选 pgvector（PostgreSQL） | Milvus | 与 MySQL 生态不同，pgvector 可部署在现有 PG；若公司无 PG 则选 Chroma 轻量方案 |
| ADR-004 | 后端用 FastAPI | Django REST | FastAPI 轻量、异步友好、自带 OpenAPI 文档 |
| ADR-005 | 前端低代码优先 | 全定制 Vue | 4 周内需交付驾驶舱，低代码可先行，定制补缺 |

## 5. 核心功能模块设计

### 5.1 数据采集层

```
[数据源] → [采集适配器] → [去重清洗] → [标准化] → [消息队列] → [入库]
   │             │            │
 调度器         代理IP池      失败重试/告警
```

- **采集适配器**：每数据源一个 Spider/Adapter，统一输出标准公告对象。
- **去重策略**：URL 去重（Redis Set）+ 内容 MinHash 指纹去重。
- **反反爬**：UA 轮换、请求频率控制、代理 IP 池（免费池起步，付费池可选）、遵守 robots.txt。
- **合规**：采集 robots 协议允许范围；数据仅用于商机识别，不涉及个人信息。

### 5.2 AI处理层

#### 5.2.1 NLP解析引擎
```
公告文本 → [文本预处理(去HTML/噪声)] → [DeepSeek提示词模板] → [结构化JSON] → [校验补全]
```
- 输出字段：招标方、项目类型、预算金额、时间节点、资质要求、技术参数、改造内容、规模、资金性质、进度阶段。
- 兜底策略：解析失败走模板规则解析（正则/关键词），仍失败标记"待人工"。
- 输出采用 JSON Schema 强约束，模型输出格式错误自动重试 1 次。

#### 5.2.2 项目画像生成
将解析结果聚合为标准项目画像，含改造规模、改造内容标签集、资金性质、进度阶段等。

#### 5.2.3 向量检索（RAG）
- 产品知识库文档 → embedding（DeepSeek/text-embedding）→ 存入向量库。
- 匹配时对项目需求标签做 embedding，检索 Top-K 产品方案。

### 5.3 智能决策层

#### 5.3.1 商机评分引擎
```
score = w1*需求匹配度 + w2*预算规模 + w3*区域覆盖 + w4*时间紧迫度 + w5*竞争态势
默认权重：40/20/15/15/10，可配置化。
```
- 需求匹配度：三步式匹配综合得分（粗匹配 30% + 深度匹配 50% + 区域匹配 20%）。
- 预算规模分段：≥1000万 → 20；500-1000万 → 16；100-500万 → 12；<100万 → 6；未知 → 0（可配）。
- 时间紧迫度：距投标截止 ≤7 天 → 15；≤30 天 → 12；≤90 天 → 8；>90 天 → 5。
- 竞争态势：无已知竞品 → 10；1 家 → 7；≥2 家 → 4；竞品已中标 → 2。

#### 5.3.2 跟进策略生成
按评分段输出跟进建议与话术模板，见 SRS FR-026。

#### 5.3.3 竞品分析引擎
竞品关键词库 + 公告解析结果匹配 → 竞品中标记录 → 区域/产品策略分析。

#### 5.3.4 智能商机挖掘模块（v1.1 新增）
主动商机挖掘子系统，对应 6 张新表（见 DBD 3.15-3.20）：

- **存量项目生命周期推算**：按安装年份计算设备年龄，产出更新窗口（6-8 年临期 / 8-10 年到期 / >10 年超期），推荐对应换新动作（如 IP 两线）。
- **销售线索四维评分**：行业相关度 + 阶段 + 渠道 + 预算，百分制；渠道覆盖招标/采购意向/改造计划/立项/土地/竞品中标等。
- **集采到期预警**：战略客户合同 ≤1 年红标、超期流失标记。
- **竞品后续追踪**：竞品中标记录 → 自动生成后续标段/维保/续签追踪项。
- **诉求热点聚合**：投诉/求助按小区聚合（热度分、痛点标签、样本标题），反哺换新商机。
- 数据来源：新增 4 类采集源（`intention/planlist/approval/land`）+ 人工录入 + 真实互联网公告导入。

#### 5.3.5 AI 成本控制与原文追溯（v1.1 新增）
- **LLM 每日限额**：`DEEPSEEK_DAILY_LIMIT`（默认 150/日），`llm_quota` 计数器持久化；超限自动降级：解析走模板、核验走本地规则。
- **本地预筛**：`should_skip_llm` 按标题强信号 + 本地相关度预判，低相关直接拦截，减少无效 LLM 调用。
- **原文追溯**：商机/公告均保存 `source_url`，前端一键跳转原文。

### 5.4 应用展示层
- 商机驾驶舱：总量卡片、区域分布柱图、评分分布、跟进漏斗。
- 项目热力图：地图散点/热力 + 下钻。
- 跟进看板：商机列表、状态流转、跟进记录时间线。
- 报表中心：月度趋势、区域热度、产品需求排行，支持导出。
- 智能商机挖掘（v1.1 新增）：存量项目台账、更新商机、战略客户集采、销售线索、竞品追踪、诉求热点 6 个页面。

## 7. 非功能架构设计

### 7.1 性能
- 采集：多任务并发（Scrapy 并发 16），队列削峰。
- 查询：热点指标 Redis 缓存，列表分页 + 索引。
- 解析：异步任务池（Celery 并发 8），单条 ≤ 30s。

### 7.2 可用性
- 关键任务失败自动重试（3 次，指数退避）。
- 服务无状态化，支持多实例。

### 7.3 安全
- JWT 认证 + RBAC 授权（中间件统一鉴权）。
- 密码 BCrypt，敏感配置环境变量注入。
- HTTPS 部署，接口限流（IP + 用户维度）。

### 7.4 可观测性
- 统一日志（结构化 JSON，分级）。
- 健康检查 /health；任务执行记录表；告警接入企业微信。
