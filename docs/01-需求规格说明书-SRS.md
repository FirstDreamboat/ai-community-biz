## 1. 引言

### 1.1 编写目的
本文档定义"AI存量项目商机挖掘系统"的功能需求、非功能需求、业务规则与验收标准，作为设计、开发、测试各阶段的工作依据。读者对象：产品经理、项目经理、开发工程师、测试工程师、业务顾问。

### 1.2 项目背景
"十五五"期间我国将新开工改造城镇老旧小区 11.5 万个，2026 年中央财政安排城市更新专项资金 970 亿元。狄耐克已将老旧小区更新改造、存量项目智能化升级作为市场攻坚重点方向。当前老旧小区改造项目信息分散于各级政府网站、招投标平台、住建部门公告等渠道，人工搜集效率低、商机响应慢。本系统旨在实现从信息采集到商机转化的全链路自动化。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| 商机 | 符合狄耐克业务方向的老旧小区改造项目线索 |
| 公告 | 从数据源采集到的原始文本信息（招标公告、采购意向、政策文件等） |
| 项目画像 | 从公告中解析出的结构化项目信息集合 |
| 评分 | 对项目商机价值的综合量化评估（0-100 分） |
| RAG | 检索增强生成，用于产品知识库语义匹配 |
| 数据源 | 信息采集渠道（政府平台、物业动态、政策规划、行业资讯） |

## 2. 项目目标

| 目标 | 说明 | 衡量标准 |
|------|------|---------|
| 精准 | 自动采集全国老旧小区改造项目信息，AI 匹配狄耐克产品方案 | 商机有效准确率 ≥ 85% |
| 高效 | 商机发现效率提升 5-10 倍，从"人找信息"变为"信息找人" | 商机日采集量 50-100 条 |
| 转化 | 生成优先级排序的商机列表和定制化跟进策略 | 线索转化率提升至 15-20% |

### 2.1 关键业务指标（KPI）

| 指标 | 现状 | 目标值 |

| 销售线索转化率 | 约 5-10% | 提升至 15-20% |
| 区域覆盖率 | 依赖人工经验 | 全国全覆盖 |

## 4. 功能需求

### 4.1 数据采集模块（四源并进）

#### 4.1.1 政府招投标平台采集
- **FR-001**：定向采集中国政府采购网（ccgp.gov.cn）、各省市公共资源交易中心、住建部门官网的招标公告、采购意向、项目审批信息。
- **FR-002**：支持按省份/城市、关键词（老旧小区改造、城市更新、智慧社区、楼宇对讲、门禁、安防等）、时间范围配置采集任务。
- **FR-003**：采集任务支持手动触发与定时调度（每日/每周），调度异常自动重试（最多 3 次）。
- **FR-004**：对采集到的公告进行 URL 去重与内容指纹去重，避免重复入库。

#### 4.1.2 物业与开发商动态采集
- **FR-005**：采集头部物业公司（龙湖、保利、招商蛇口等）及地方城投公司的项目动态、供应商征集公告。
- **FR-006**：对供应商征集类公告标记"征集类型"并优先进入解析队列。

#### 4.1.3 政策与规划信息采集
- **FR-007**：自动抓取各级政府的城市更新规划、老旧小区改造年度计划、重点改造片区名单，形成政策库。
- **FR-008**：政策信息与项目信息建立关联（如某政策下辖的具体改造项目清单）。

#### 4.1.4 行业资讯与展会采集
- **FR-009**：采集安防行业媒体、智慧社区论坛、行业展会信息，识别潜在商机线索。

#### 4.1.5 采集通用要求
- **FR-010**：遵守 robots 协议，支持请求频率控制、代理 IP 池、UA 轮换等反反爬策略。
- **FR-011**：采集失败产生告警，支持失败记录查询与重新采集。

### 4.2 AI智能解析模块

#### 4.2.1 公告自动解析
- **FR-012**：对非结构化公告进行语义解析，自动提取核心字段：招标方、项目类型、预算金额、时间节点、资质要求、技术参数。
- **FR-013**：预算金额支持单位归一化（元/万元/亿元）与缺失估算标记。

#### 4.2.2 项目画像生成
- **FR-014**：自动生成项目画像，至少包含：
  - 改造规模：户数、楼栋数、建筑面积
  - 改造内容：对讲系统、门禁、停车、安防、监控、照明等
  - 资金性质：中央财政、地方配套、自筹
  - 进度阶段：规划、招标、施工

#### 4.2.3 语义理解与分类
- **FR-015**：利用 NLP 判断项目与狄耐克业务关联度，自动分类为"高相关 / 中相关 / 低相关"。
- **FR-016**：解析结果支持人工修正，修正记录用于模型持续优化。

### 4.3 智能匹配模块（商机评分）

#### 4.3.1 产品知识库
- **FR-017**：构建狄耐克全系列产品与解决方案向量化知识库，至少覆盖：IP两线公寓对讲系统、数字楼宇对讲系统、智慧社区解决方案、智慧停车、紧急求助等。
- **FR-018**：知识库支持增删改查，更新后向量索引自动增量重建。

#### 4.3.2 双向匹配运算（三步式）
- **FR-019**：第一轮——项目需求标签与产品能力标签的粗匹配。
- **FR-020**：第二轮——项目改造条件（如"布线难"）与公司技术方案（如"无需重铺线路"）的深度语义匹配。
- **FR-021**：第三轮——项目区域与办事处覆盖能力匹配（60+ 直属办事处、30+ 经销网点）。

#### 4.3.3 商机评分模型（百分制）

| 维度 | 分值 | 说明 |
|------|------|------|
| 需求匹配度 | 40 | 项目需求与公司产品方案契合程度 |
| 预算规模 | 20 | 项目预算金额大小（分段计分） |
| 区域覆盖 | 15 | 是否在公司办事处覆盖范围内 |
| 时间紧迫度 | 15 | 投标截止时间、项目启动时间 |
| 竞争态势 | 10 | 已知竞争对手情况 |

- **FR-022**：评分规则支持配置化调整（权重、分段阈值），由业务顾问维护。
- **FR-023**：评分结果可追溯（展示各维度得分明细与评分依据）。

### 4.4 商机推送与跟进模块

#### 4.4.1 优先级排序输出
- **FR-024**：按综合评分从高到低排序，每日/每周自动生成商机推荐列表，推送至销售人员。
- **FR-025**：推送方式支持站内消息、邮件、企业微信/钉钉 Webhook（可配置）。

#### 4.4.2 定制化跟进策略
- **FR-026**：自动生成跟进建议：
  - 高评分（≥70）：建议立即联系、准备定制化方案
  - 中评分（40-69）：建议进一步调研、准备标准方案
  - 低评分（<40）：建议持续关注、定期复查
- **FR-027**：跟进记录全流程留痕（时间、人员、动作、结论），状态流转：新建→跟进中→已投标→已中标/已丢标→关闭。

#### 4.4.3 竞品监测
- **FR-028**：自动监测竞品（安居宝、立林等）在老旧小区改造项目中的中标情况，分析优势区域与产品策略。
- **FR-029**：竞品监测结果在项目详情与报表中展示。

### 4.5 数据可视化模块

#### 4.5.1 商机驾驶舱
- **FR-030**：实时展示全国商机总量、区域分布、评分分布、跟进状态。
- **FR-031**：支持按时间、区域、评分段、相关度等维度筛选下钻。

#### 4.5.2 项目热力图
- **FR-032**：地图上展示各区域老旧小区改造项目密度，支持省/市/区县级下钻。
- **FR-033**：地图支持与商机列表联动（点选地图区域过滤列表）。

#### 4.5.3 趋势分析
- **FR-034**：月度商机变化趋势、区域热度排行、产品需求排行。
- **FR-035**：报表支持导出（Excel/CSV）。

### 4.6 系统管理
- **FR-036**：用户与角色管理（RBAC）。
- **FR-037**：数据源配置管理（增删改查、启停、调度频率）。
- **FR-038**：操作审计日志。
- **FR-039**：系统参数配置（推送渠道、评分权重、关键词库等）。

### 4.7 智能商机挖掘模块（v1.1 新增）
> 背景：除"全网招标"被动搜索外，通过存量项目生命周期、采购意向、改造计划、立项审批、土地出让、竞品后续、诉求热点等主动挖掘商机。

#### 4.7.1 存量项目生命周期台账
- **FR-040**：建立存量项目台账（已交付/在管项目），记录项目名称、小区、省份城市、子系统、设备品牌、安装年份、质保期、预算、联系人、备注。
- **FR-041**：按设备年限自动推算更新窗口：
  - 6-8 年：临期（即将进入更新窗口）；
  - 8-10 年：到期（建议跟进）；
  - \>10 年：超期（建议 IP 两线等产品换新）。
- **FR-042**：支持台账批量导入（人工/脚本）与逐条维护。

#### 4.7.2 更新商机生成
- **FR-043**：扫描存量台账，自动生成更新商机（含设备年龄、窗口状态、推荐动作、预估预算），支持一键重新生成/刷新。

#### 4.7.3 战略客户集采台账
- **FR-044**：维护集采/战略客户台账（客户名称、合作类型、产品线、合同起止年份、年度金额、联系人）。
- **FR-045**：到期预警：合同 ≤1 年到期标红预警，已超期标记流失，防集采丢单。

#### 4.7.4 销售线索管理
- **FR-046**：销售线索四维评分（行业相关度 + 阶段 + 渠道 + 预算，百分制），支持人工录入与系统采集。
- **FR-047**：线索渠道覆盖：全网招标、采购意向、改造计划、立项审批、土地出让、竞品中标、销售报备、展会、行业活动、电话营销、老客户转介绍等。

#### 4.7.5 竞品后续追踪
- **FR-048**：追踪竞品中标项目（中标金额、中标时间、来源链接），跟踪竞品后续标段/维保/续签窗口。
- **FR-049**：支持从竞品中标记录一键生成后续追踪条目。

#### 4.7.6 诉求热点挖掘
- **FR-050**：采集小区门禁/对讲/安防类诉求（12345 工单、媒体求助、投诉报道），按小区聚合热点（投诉量、热度分、痛点标签、样本标题、来源链接），反哺换新商机。

### 4.8 数据源类型扩展（v1.1 新增）
- **FR-051**：在原有 `gov/property/policy/news/api` 基础上，新增 4 类商机挖掘数据源：
  - `intention`：采购意向公开（比正式招标早 30-60 天）；
  - `planlist`：改造计划/改造名单（目标小区客户清单）；
  - `approval`：立项/审批公示（比招标早 6-12 个月）；
  - `land`：土地出让/规划公示（预判未来建设需求）。
- **FR-052**：新类型数据源走统一采集器（`category = ds_type`），采集公告自动标记类型。
- **FR-053**：调度频率：意向类每日凌晨 0-1 点、计划类 1-2 点、立项/土地类 2-3 点，错峰执行（可配置）。

### 4.9 AI 成本控制与原文追溯（v1.1 新增）
- **FR-054**：DeepSeek 每日调用限额（`DEEPSEEK_DAILY_LIMIT`，默认 150 次/日，可配置），超限自动降级：解析走模板、核验走本地规则，不再消耗额度。
- **FR-055**：本地预筛（`should_skip_llm`）：标题无强商机信号且本地相关度低时，直接走模板解析/判不通过，减少无效 LLM 调用。
- **FR-056**：商机详情与列表展示"原文链接"（`source_url`），支持一键跳转查看公告原文，保证消息可溯源。

## 5. 非功能需求

### 5.1 性能需求
| 编号 | 需求 | 指标 |
|------|------|------|
| NFR-001 | 商机采集吞吐 | ≥ 100 条/天/源，峰值支撑 500 条/天 |
| NFR-002 | 页面响应时间 | 驾驶舱首屏 ≤ 3s，列表查询 ≤ 2s |
| NFR-003 | 解析处理时效 | 单条公告解析 ≤ 30s，批量解析吞吐 ≥ 10 条/分钟 |
| NFR-004 | 并发用户 | 支撑 50 并发在线用户 |

### 5.2 可用性需求
- **NFR-005**：系统可用性 ≥ 99.5%（月度）。
- **NFR-006**：数据采集、解析、推送等核心任务故障自动重试，关键任务失败告警。

### 5.3 安全性需求
- **NFR-007**：用户认证采用账号密码 + JWT Token，密码加密存储（BCrypt）。
- **NFR-008**：RBAC 权限控制，接口级鉴权。
- **NFR-009**：采集遵守 robots 协议与《数据安全法》，敏感个人信息脱敏。
- **NFR-010**：操作审计日志保留 ≥ 180 天。

### 5.4 兼容性与可扩展性
- **NFR-011**：支持 Chrome/Edge 最新两个大版本。
- **NFR-012**：数据源可插拔扩展，新增数据源无需改核心逻辑。
- **NFR-013**：未来可扩展至智慧医院、智慧酒店等业务线（业务线字段预留）。

### 5.5 可维护性
- **NFR-014**：日志分级记录（DEBUG/INFO/WARN/ERROR），支持集中查询。
- **NFR-015**：关键模块提供健康检查接口（/health）。

## 6. 业务规则

| 编号 | 规则 |
|------|------|
| BR-001 | 同一公告按 URL + 内容哈希双重去重，重复数据不重复计分 |
| BR-002 | 商机评分仅对"已解析 + 已匹配"状态的项目生成 |
| BR-003 | 人工修正解析结果后，该记录标记为"已人工确认"，优先级高于 AI 结果 |
| BR-004 | 高评分商机 24 小时内必须完成首次跟进，逾期自动提醒 |
| BR-005 | 商机关闭（中标/丢标/无效）后 30 天内不允许自动重新激活，除非人工操作 |
| BR-006 | 评分规则变更立即生效，并对存量商机进行重新评分（可选批量重算） |

## 8. 验收标准

### 8.1 功能验收
| 验收项 | 标准 |
|--------|------|
| 数据采集 | 4 类数据源全部接入，日采集量达 50-100 条 |
| 公告解析 | 核心字段解析准确率 ≥ 85%（抽样 200 条） |
| 商机匹配 | 高相关判定准确率 ≥ 80%（业务顾问抽样复核） |
| 商机推送 | 每日/每周推荐列表自动生成并推送成功 |
| 可视化 | 驾驶舱、热力图、趋势分析可正常查看与下钻 |
| 跟进闭环 | 跟进状态流转完整，竞品监测正常输出 |
| 智能商机挖掘 | 存量台账可维护，生命周期推算正确，更新商机一键生成，线索评分/集采预警/诉求聚合可用 |
| 原文追溯 | 商机列表与详情均可跳转查看公告原文 |
| AI 成本控制 | 每日 LLM 调用不超限额，超限自动降级不影响主流程 |

### 8.2 非功能验收
- 性能指标满足 5.1 节要求（压测报告佐证）。
- 安全项：越权访问、未授权接口调用测试通过。
- 可用性：故障演练中核心任务可自动恢复。

## 10. 附录：需求变更流程

1. 需求提出方填写《需求变更申请单》（变更内容、影响范围、优先级）。
2. 项目经理组织评审，评估影响（工作量、排期、风险）。
3. 评审通过后更新本文档与需求跟踪矩阵，版本号递增。
4. 变更同步至设计与测试基线。
