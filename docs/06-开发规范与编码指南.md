## 1. 总则

- 目标：统一代码风格、保证可读性/可维护性、降低协作成本。
- 强制条款用 **必须**，建议条款用 **建议**。
- 所有代码必须通过代码评审（Code Review）后合入主干。

## 3. Python 编码规范

### 3.1 命名
| 对象 | 规范 | 示例 |
|------|------|------|
| 模块/包 | 小写下划线 | `opportunity_service.py` |
| 类 | 大驼峰 | `ScoreEngine` |
| 函数/方法 | 小写下划线 | `compute_total_score()` |
| 常量 | 全大写下划线 | `MAX_RETRY_TIMES = 3` |
| 私有成员 | 单下划线前缀 | `_dedup()` |
| 数据库列 | 小写下划线 | `total_score` |

### 3.2 代码风格
- 缩进 4 空格；行宽 ≤ 100。
- 字符串一律单引号，文档字符串用双引号三引号。
- 类型注解必须（Python 3.10+），复杂类型用 `typing`。
- 禁止 `except: pass`，必须捕获具体异常并记录日志。
- 函数单一职责，单函数 ≤ 50 行（建议）。

### 3.3 示例
```python
from datetime import datetime
from typing import Optional

from sqlalchemy import select

MAX_RETRY_TIMES = 3


def get_opportunity_by_id(opp_id: int) -> Optional[dict]:
    """按ID查询商机，不存在返回 None。"""
    if opp_id <= 0:
        raise ValueError("opp_id must be positive")
    stmt = select(Opportunity).where(Opportunity.id == opp_id)
```

## 4. 数据库开发规范
- 所有表结构变更通过迁移脚本（Alembic）管理，禁止手工改生产库。
- 字段命名、类型遵循《03-数据库设计说明书》。
- 查询必须走索引；禁止在查询条件中对列使用函数。
- 禁止 `SELECT *`；大数据量分页用 `LIMIT/OFFSET` 或游标。
- 所有写入操作记录 `created_at/updated_at`。
- 表变更需同步更新 DBD 文档。

---

## 5. 接口开发规范
- 遵循《04-API接口设计说明书》统一返回结构与错误码。
- 接口必须校验参数（Pydantic 模型）与权限。
- 新接口必须附带幂等/并发处理（推送等场景）。
- 敏感字段（Token、密钥）禁止出现在响应与日志中。

---

## 6. 爬虫开发规范
- 必须设置 `ROBOTSTXT_OBEY=True`（除非数据源明确开放）。
- 必须设置下载延迟与并发上限，遵守站点频率限制。
- 必须实现失败重试与降级（备用数据源）。
- 采集代码与数据合规审查：不采集个人信息、不绕行登录墙（除非授权）。
- 新增数据源必须同步登记到 `data_source` 配置与文档。

---

## 7. 代码管理规范

### 7.1 分支模型（Git Flow 简化版）
```
main（主干，仅发布）
 └─ develop（开发主线）
     ├─ feature/opp-scoring     功能分支
     ├─ bugfix/parse-null       缺陷分支
     └─ release/v1.0.0          发布分支
```

### 7.2 提交规范（Conventional Commits）
```
<type>(<scope>): <subject>

type: feat | fix | docs | style | refactor | test | chore
示例：feat(scoring): 增加预算分段计分规则
      fix(parser): 修复投标截止字段解析为 null 的问题
```

### 7.3 评审要求
- 所有合入 `develop` 的代码必须过评审。
- 评审关注：正确性、性能、安全、命名、测试覆盖。
- 禁止直接向 `main` 提交（发布除外）。

---

## 8. 测试规范
- 单测：每个核心函数至少一个用例；覆盖正常、边界、异常。
- 服务级测试：pytest + TestClient，测接口契约。
- 测试数据与生产隔离，禁止使用真实个人信息。
- 测试文件命名：`test_<module>.py`。

---

## 9. 文档规范
- 代码内必要注释用中文，注释解释"为什么"而非"是什么"。
- 接口变更同步更新《04-API接口设计说明书》。
- 每周五提交"本周开发小结"到项目文档目录。

---

## 10. 安全红线（必须遵守）
| 编号 | 红线 |
|------|------|
| SEC-01 | 禁止将密钥/密码提交到代码仓库 |
| SEC-02 | 禁止 SQL 字符串拼接，一律参数化 |
| SEC-03 | 禁止在日志打印 Token、密码、完整手机号 |
| SEC-04 | 越权测试必须覆盖（同角色跨用户访问） |
| SEC-05 | 第三方依赖升级前必须评估漏洞（pip-audit） |
| SEC-06 | 采集行为必须符合 robots 协议与数据合规要求 |
