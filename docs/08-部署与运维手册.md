## 3. 配置文件说明

### 3.1 环境变量（.env 示例）
```
# 数据库
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=biz_user
MYSQL_PASSWORD=******
MYSQL_DB=opportunity_system

# Redis
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=

# AI
DEEPSEEK_API_KEY=sk-******
DEEPSEEK_BASE_URL=https://api.deepseek.com
EMBEDDING_MODEL=deepseek-embed
# v1.1 新增：DeepSeek 每日调用限额，超限自动降级（模板/本地规则）
DEEPSEEK_DAILY_LIMIT=150

# 安全
JWT_SECRET=请替换为随机长字符串
JWT_EXPIRE_HOURS=24

# 推送（v1.2：企微/钉钉/通用 webhook 三渠道真实下发；留空则该渠道不启用）
PUSH_WEBHOOK_URL=https://example.com/webhook        # 通用 webhook（接收 {type,title,content,sent_at} JSON）
PUSH_WECOM_WEBHOOK_URL=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=******   # 企业微信群机器人
PUSH_DINGTALK_WEBHOOK_URL=https://oapi.dingtalk.com/robot/send?access_token=******   # 钉钉群机器人
SMTP_HOST=
SMTP_PORT=465
SMTP_USER=
SMTP_PASSWORD=

# 采集代理池（v1.2 可选）：sys_config 表 collector.proxy_pool_url，
# 数据源 proxy_enabled=1 时经代理池出口（合规：仍遵守 robots/限速/重试，不用于绕过封禁验证码）

# 其他
LOG_LEVEL=INFO
```

### 3.2 docker-compose.yml 结构（要点）
```
services:
  mysql:      # 端口 3306，挂载数据卷，初始化SQL
  redis:      # 端口 6379
  backend:    # api-gateway（FastAPI），暴露 8000
  collector:  # 采集服务
  ai:         # AI 服务
  nginx:      # 端口 80/443，反代 backend + 前端静态
volumes:
  mysql_data:
  uploads:
```

## 4. 部署步骤

### 4.1 首次部署
```bash
# 1. 拉取代码
git clone <repo-url> && cd <project>

# 2. 配置环境变量
cp .env.example .env && vi .env

# 3. 构建并启动
docker compose build
docker compose up -d

# 4. 初始化数据库
docker compose exec mysql sh -c 'mysql -uroot -p$MYSQL_ROOT_PASSWORD < /docker-entrypoint-initdb.d/01_schema.sql'

# 5. 验证
curl http://localhost:8000/api/v1/health
```

### 4.2 升级部署
```bash
git pull
docker compose build backend collector ai
docker compose up -d
# 执行数据库迁移（如有）
docker compose exec backend alembic upgrade head
```

### 4.3 回滚
```bash
docker compose down
git checkout <上一版本tag>
docker compose up -d
```

## 5. 采集任务运维

### 5.1 查看任务状态
- 采集任务记录：`GET /api/v1/collector-tasks`。
- 数据库查询：
```sql
SELECT source_id, status, new_count, dup_count, fail_count, started_at, finished_at
FROM collector_task_log ORDER BY id DESC LIMIT 20;
```

### 5.2 手动触发
```bash
# 通过接口
curl -X POST http://<host>/api/v1/data-sources/1/run -H "Authorization: Bearer <token>"
```

### 5.3 常见问题
| 问题 | 处理 |
|------|------|
| IP 被封 | 确认代理池配置，降低频率，切换备用源 |
| 站点改版解析失败 | 更新 Spider 选择器，启用模板兜底 |
| 采集积压 | 检查消息队列堆积，扩容 worker |

## 6. 监控与告警

### 6.1 健康检查
```bash
curl http://localhost:8000/api/v1/health
# {"code":0,"data":{"status":"ok","components":{"mysql":"up","redis":"up",...}}}
```

### 6.2 监控项
| 对象 | 指标 |
|------|------|
| 服务 | 进程存活、CPU/内存、/health 状态 |
| MySQL | 连接数、慢查询、磁盘 |
| Redis | 内存使用、队列长度（关键：解析/推送队列） |
| 采集任务 | 成功率、新增数、失败数 |
| 推送任务 | 成功率、失败原因 |

### 6.3 告警规则
| 规则 | 级别 | 通知 |
|------|------|------|
| 服务宕机/健康检查失败 | P0 | 立即企微 |
| 采集连续 3 次失败 | P1 | 企微+邮件 |
| 解析队列积压 > 1000 | P1 | 企微 |
| 推送失败率 > 20% | P1 | 企微 |
| 磁盘使用率 > 80% | P2 | 邮件 |

### 6.4 告警接入（企微 Webhook）
```bash
curl 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=***' \
  -H 'Content-Type: application/json' \
  -d '{"msgtype":"text","text":{"content":"【告警】采集任务失败 x3"}}'
```

## 7. 日志管理
- 日志目录：`/var/log/opportunity/`（容器内 `/app/logs`）。
- 分级：DEBUG/INFO/WARN/ERROR，生产 WARN 起。
- 结构化 JSON 日志，包含 `trace_id`。
- 定期归档：日志保留 30 天，审计日志保留 180 天（cron 清理）。

## 8. 数据备份与恢复

### 8.1 备份策略
| 数据 | 频率 | 保留 |
|------|------|------|
| MySQL 全量 | 每日 02:00 | 30 天 |
| MySQL binlog | 实时 | 7 天 |
| 上传文件/导出 | 每日增量 | 30 天 |
| 向量库索引 | 每周 | 4 周（可重建） |

### 8.2 备份命令
```bash
# MySQL 全量备份
docker compose exec mysql mysqldump -uroot -p$MYSQL_ROOT_PASSWORD \
  --single-transaction opportunity_system > backup/opp_$(date +%F).sql

# 恢复
docker compose exec -T mysql mysql -uroot -p$MYSQL_ROOT_PASSWORD opportunity_system < backup/opp_2026-08-21.sql
```

### 8.3 备份验证
- 每月进行一次恢复演练。
- 每日备份任务完成后检查备份文件大小非零。

## 9. 故障处理手册

| 故障 | 排查步骤 | 恢复措施 |
|------|---------|---------|
| 服务不可用 | 查看容器状态/日志 | `docker compose restart <svc>` |
| 数据库连接失败 | 检查 MySQL 存活/密码/网络 | 重启 MySQL，检查 .env |
| Redis 内存爆 | 检查 key 大小、队列积压 | 清理缓存，扩容队列消费 |
| AI 接口超时 | 检查 DeepSeek 配额/网络 | 开启熔断降级为模板解析 | 
| AI 接口报"额度已用尽" | `DEEPSEEK_DAILY_LIMIT` 触发每日限额 | 正常降级行为；次日自动恢复，或调大限额/更换 Key |
| 推送失败 | 查看 push_record 错误信息 | 修正 Webhook/SMTP 配置后重推 |
| 采集死循环 | 检查调度与去重 | 停用数据源，排查规则 |
| 磁盘满 | df -h 定位 | 清理日志/备份，扩容 |

## 10. 安全运维
- 修改默认口令；密码复杂度策略。
- 服务器仅开放必要端口（80/443/SSH），数据库不对外。
- HTTPS 证书定期续期（certbot 自动）。
- .env 权限 600，禁止入库。
- 依赖漏洞定期扫描，高危漏洞 48h 内处理。
